Наивная рекурсивная реализация чисел Фибоначчи неэффективна из‑за экспоненциального числа повторных вычислений.
Суть проблемы:
При вычислении fib(n) = fib(n−1) + fib(n−2) подзадачи перекрываются — например, fib(n−2) вычисляется дважды (один раз в fib(n−1), второй раз напрямую). Это порождает дерево вызовов с огромным числом дублирующих вычислений.
Последствия:
1. Временная сложность: O(ϕn) (экспоненциальная, где ϕ≈1,618).Например, fib(40) требует ~340 млн вызовов.
2. Пространственная сложность: O(n) (из‑за глубины рекурсии), что менее критично, но всё равно накладывает ограничения.
Вывод:
Алгоритм прост для понимания, но практически непригоден для n>35–40 из‑за взрывного роста времени выполнения. Для эффективной реализации используют мемоизацию или итеративный подход (O(n) времени и памяти).
