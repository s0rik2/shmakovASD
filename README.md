Практическое задание. Вариант 8. Реализуйте рекурсивную функцию для подсчета суммы элементов массива.

Рекурсивная функция для подсчёта суммы элементов массива.
Как работает алгоритм:

1. Проверяем базовый случай: если длина диапазона равна 0, возвращаем 0 (сумма пустого массива); если равна 1, возвращаем единственный элемент (if size <= 1: return arr[0] if size == 1 else 0).

2. Делим задачу: рассматриваем последний элемент массива и оставшуюся часть (без последнего элемента).

3. Рекурсивно вычисляем сумму оставшейся части массива (sum_rest = arraySum(arr, size - 1)).

4. Комбиним результат: прибавляем последний элемент к сумме оставшейся части (return arr[size - 1] + sum_rest).

5. Возвращаем итоговую сумму на предыдущий уровень рекурсии.

Алгоритм последовательно «отщипывает» последний элемент, сводит задачу к сумме массива меньшего размера, пока не дойдёт до базового случая. На обратном ходу рекурсии накапливает сумму, складывая сохранённые элементы.

Формат ввода/вывода

Ввод: массив целых чисел arr и его длина size.

Вывод: целое число — сумма всех элементов массива.

Контрольный вопрос №3. Почему наивная рекурсивная реализация чисел Фибоначчи неэффективна?

Наивная рекурсивная реализация чисел Фибоначчи неэффективна из‑за экспоненциального числа повторных вычислений.

Суть проблемы:
При вычислении fib(n) = fib(n−1) + fib(n−2) подзадачи перекрываются — например, fib(n−2) вычисляется дважды (один раз в fib(n−1), второй раз напрямую). Это порождает дерево вызовов с огромным числом дублирующих вычислений.
Последствия:
1. Временная сложность: O(ϕn) (экспоненциальная, где ϕ≈1,618).Например, fib(40) требует ~340 млн вызовов.
2. Пространственная сложность: O(n) (из‑за глубины рекурсии), что менее критично, но всё равно накладывает ограничения.

Вывод:
Алгоритм прост для понимания, но практически непригоден для n>35–40 из‑за взрывного роста времени выполнения. Для эффективной реализации используют мемоизацию или итеративный подход (O(n) времени и памяти).
